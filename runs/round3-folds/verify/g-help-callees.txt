 What this symbol references: fan-out BFS over the `refs` table (same store and 
 confidence rules as `find-callers`; the graph is textual and unbound by        
 design). A callee is identified by its TARGET, not by the call site — this     
 walk answers "what does this symbol reach", so one target reached twice is one 
 callee. The opposite of `find-callers`, deliberately. An answer the depth or   
 node cap left incomplete reports `truncated` / `omitted` in JSON and a `note:` 
 line in the tree. The subject NAME is reported too: JSON carries `match_count` 
 and, when the name has several definitions, an `ambiguity` block, with         
 `targets` on each direct callee naming the definition it was reached from.     
 Text mode prints the tree plus one line saying the name resolved to several    
 definitions. For references TO a symbol across both stores use                 
 `find-references`.
