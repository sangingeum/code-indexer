# Architecture decision records

Decision records for the code-indexer overhaul. Each one settles a question the baseline audit left open (`docs/overhaul-baseline-audit.md`, section 11) and records the disagreement where the audit, the proposal or a reviewed requirement got it wrong.

| Record | Status | Decision in one line |
|---|---|---|
| [0001 -- core and extension separation](0001-core-and-extension-separation.md) | accepted | Indexing, structural query and lexical search install and run with no service; embedding and vector storage are an optional extension, the manifest stores chunk text so a pass can build a complete index with vectors off, and three version axes carry a policy matrix that never mixes vectors across models. |
| [0002 -- symbol identity and structural search](0002-symbol-identity-and-structural-search.md) | accepted | A symbol is identified by `(file, qualified name, kind, declaration hash)` with a revision-scoped surrogate id that an edit plan may not use as a locator; references keep the observed name and gain a nullable resolved target later; structural filters extend `find-symbol`; ambiguity returns candidates, never a pick. |
| [0003 -- read-only and staleness contract](0003-read-only-and-staleness-contract.md) | accepted | Read commands never write; staleness is reported in text and JSON as fresh, stale or unknown and repaired only on an explicit `--refresh`; a failed query exits non-zero; an unscoped query resolves one project, attempts one embed and stops at a wall budget. |
| [0004 -- the edit plan and its lifecycle](0004-edit-plan-and-apply-lifecycle.md) | accepted (section 7's regex-fallback example and its "in the index as well" sentence are superseded by 0010; the section's rule is not) | A plan is an immutable JSON document named by the hash of its own canonical bytes, so show, validate and apply need no mutable plan store; it targets ADR-0002's line-free locator plus a file hash and a per-edit region hash, reports structural identity and never semantic, carries no columns and no UTF-16 positions, refuses overlap instead of ordering it, and claims only the bytes and parse rungs of validation. |
| [0005 -- applying a plan through filekeeper, and recovery](0005-filekeeper-apply-and-recovery.md) | accepted | A plan is applied as one hash-guarded line-range mutation per edit after a read-only pre-pass, giving refuse-before-first-mutation, per-file atomicity, reverse-order undo and no cross-file atomicity; patch application is rejected because keeper 0.1.8 gives it no hash guard and relocates hunks, a partial failure stops and reports per file rather than auto-undoing, and there is no direct-write fallback. |
| [0006 -- language-server provider strategy](0006-language-server-provider-strategy.md) | accepted | The provider interface and its contract suite land against a stub before any real server, Python is the first language on measured workload with the install left to the owner, capabilities are queried per provider and never assumed, UTF-16 positions are converted once at the adapter boundary into bytes and 1-based lines, and a failed semantic operation fails closed rather than falling back to text replacement. |
| [0007 -- the MCP surface](0007-mcp-surface-decision.md) | accepted | MCP survives only as an optional extra with eight read-only tools, a relay that keeps the CLI's streams and exit code, and a usage record whose first release cycle decides whether it stays; the catalog drops from eighteen tools to eight before it is judged. |
| [0008 -- the product name](0008-product-naming.md) | accepted | The tool keeps the name `code-indexer` for this phase, because the name is not the defect and a rename would land in the same release as three behaviour migrations; the rename cost is recorded as an inventory, and five stated conditions gate any later change. |
| [0009 -- the agent surface](0009-agent-surface-skill-layout.md) | accepted | The documentation an agent loads is one entry document of at most 120 lines and 8 KiB carrying the decision tree, the command roster with its read-or-write classes, the exit codes and the staleness rule, plus reference files read on demand whose command sections are generated from the registry; the installed skill is a copy whose digest the documentation test pins. |
| [0010 -- the parse verdict describes the parser](0010-the-parse-verdict-describes-the-parser.md) | accepted (owner ratification 2026-11-08) | The verdict reports what the parser did and only the absence of an AST is `parse_unavailable`, so a file the parser read and found no declarations in is `parsed` while its single fallback chunk for lexical search stays a search artifact; the no-grammar and parser-exception paths keep `parse_unavailable` and keep blaming the missing reader. |

The order in which these records land is `docs/overhaul-plan.md`, which is ratified alongside them and decides no behaviour of its own.

## Conventions

- **Numbering** is sequential, four digits: `NNNN-concept-name.md`. A record is never renumbered.
- **Status** is one of `proposed`, `accepted`, `superseded`, `rejected`.
  A record is `proposed` until the owner ratifies it.
- **Sections** are fixed: the one-paragraph decision first, then context, decision, the requirements the record resolves, alternatives, consequences, and what the record does not decide. A reader who reads only the first paragraph still learns the answer.
- **Provenance** is cited inline: an audit section, a source path with lines, or a command with its output. A number without a source does not belong in a record.
- **Measurement**: a measurement is cited as the command that produces it and a short excerpt of what it printed, quoted where the number is used -- `keeper --version` -> `keeper 0.1.8`, `git ls-files | xargs rg -il 'code[-_ ]?indexer' | wc -l` -> `206`, or a read-only query against the manifest and its result. No record cites an artifact path: a source a reader cannot open is not a source, and a measurement that depends on a file kept outside the published tree does not satisfy this convention. A measurement whose procedure is too long to quote is not taken.
- **Language** is natural: concepts are named in words, not coordinate labels. `--` rather than em dashes. Paths are repository-relative; no host paths.
- **Disagreement is written down.** Where a record rejects the proposal, the audit or a reviewed requirement, the disagreement, the better rule and the evidence are all in the record. A record that agrees with everything has failed.
- **Amendment**: a decision changes only by a superseding record, which names what it supersedes. Two narrow exceptions. **Before a record is accepted**, a fold applied in place is not a supersession: a proposal whose own gate found it contradicting a sibling record is corrected where it is written, its status stays `proposed`, and the gate record is the provenance for the fold -- otherwise the set would hold two answers to one question and no ratified one. **Typos and citation corrections** are fixed in place at any time. After acceptance, a correction that changes what a record decides is a superseding record.
